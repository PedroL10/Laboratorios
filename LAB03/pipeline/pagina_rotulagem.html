Como rotular (leia antes de começar)

Rotule com base no que você lê aqui e nos links. Não consulte colegas nem a saída do pipeline. O progresso fica salvo neste navegador: pode fechar e voltar depois.

Tipo do projeto (uma vez por repositório):

  • biblioteca/framework: usado como dependência por outro código (pacote npm/PyPI/crate, SDK, framework).
  • aplicação/serviço: usado diretamente pelo usuário final (app web/desktop/mobile, servidor, plataforma, banco de dados).
  • ferramenta CLI: usado principalmente pelo terminal (compilador, linter, ferramenta de build, utilitário).
  • outro: listas, documentação, modelos, conjuntos de dados, configurações.

As releases representam entregas reais ao usuário? sim se cada release entrega algo utilizável (versão do app, pacote publicado, binário); não se são automáticas/nightly/internas ou não mudam o que o usuário recebe; incerto se não dá para saber.

Esta release é corretiva? sim se o objetivo principal é corrigir um defeito recente: correção de bug, falha de segurança, revert de uma mudança que quebrou algo, hotfix. não se é principalmente funcionalidade nova, release programada com várias mudanças, só atualização de dependências, documentação ou manutenção. Em release mista, decida pelo que predomina ou pelo que as notas destacam primeiro. O número da versão é uma pista, não a regra.
