Laboratorio de Experimentacao de Software — Lab01

Caracteristicas de repositorios populares no GitHub

O que os 1.000 repositorios mais estrelados tem em comum — e onde essa intuicao falha.

Grupo Pedro Luis · Enrico Bessa · Pericles Pires Amostra 1.000 repositorios · API GraphQL propria Repositorio github.com/PedroL10/Lab01Exp

Contexto

O que 1.000 repositorios podem nos dizer sobre popularidade?

Repositorios populares costumam ser tratados como referencia implicita de qualidade e boas praticas, mas popularidade nao descreve, por si so, maturidade, atividade ou capacidade de manutencao. Investigamos isso empiricamente coletando os 1.000 repositorios publicos com mais estrelas do GitHub, via uma query GraphQL escrita pelo proprio grupo.

Metodologia

Quatro decisoes que sustentam os numeros a seguir

Coleta propria

Script GraphQL escrito do zero, sem biblioteca de terceiros para a API do GitHub. Paginacao em lotes de 10 repositorios com retry e backoff exponencial, porque lotes maiores excediam o limite de custo da API em repositorios com trackers grandes.

Teto de 1.000 resultados

A propria API de busca do GitHub limita qualquer consulta ordenada a 1.000 itens, mesmo com paginacao correta — confirmamos isso na pratica, nao e um limite nosso.

Data de referencia fixa

Analise fixada em 24/08/2026, 00h UTC. Isso torna idade do repositorio e tempo desde a ultima atualizacao reproduziveis por qualquer pessoa que rodar o script depois.

Mediana como padrao

PRs aceitas, releases e tempo sem atualizacao tem distribuicao assimetrica e outliers fortes (ex.: media de PRs e 5,5x maior que a mediana) — por isso mediana e a medida central usada em todo o estudo.

Inovacao do grupo — parte 1 de 2

RQ08 — De onde veio essa pergunta

Como surgiu

Ao segmentar a RQ07 por linguagem, o grupo "Nao informado" (repositorios sem primaryLanguage detectada) aparecia com numeros muito destoantes dos demais. Em vez de descartar isso como dado incompleto, decidimos investigar o padrao diretamente.

O que significa tecnicamente

O campo primaryLanguage vem nulo quando o classificador de linguagem do GitHub (Linguist) nao detecta uma linguagem de codigo dominante. Isso nao significa que o repositorio esta vazio — significa que ele nao tem uma linguagem de programacao majoritaria.

Por que conta como inovacao

RQ05 e RQ07 tratam de qual linguagem e usada. RQ08 usa uma variavel diferente, nao pedida no enunciado: a ausencia de uma linguagem dominante como proxy de "isso e software em desenvolvimento ativo, ou conteudo curado/documentacao?"

Verificacao manual (amostra)

Conferimos alguns casos do grupo "sem linguagem" a mao, confirmando que sao listas curadas ou documentacao, nao erro de deteccao:

Limite honesto: correlacao, nao causalidade

Nao controlamos variaveis de confusao. A explicacao mais provavel e composicional: o grupo sem linguagem primaria e dominado por listas curadas e documentacao, que por natureza nao seguem ciclo de release nem recebem PR de codigo como software ativo.

Conclusao

O que fica depois de 1.000 repositorios

  • Repositorios muito populares tendem a ser maduros, receber muitas contribuicoes, manter alta taxa de issues fechadas e ser atualizados com frequencia — mas nenhuma dessas caracteristicas e universal.
  • Quase um terco nao usa releases formais; parte dos repositorios populares e documentacao, lista curada ou mirror, com dinamica propria de manutencao.
  • Popularidade da linguagem nao prediz, sozinha, intensidade de contribuicao por repositorio (RQ07).
  • A ausencia de linguagem primaria detectada esta associada a manutencao bem menos frequente (RQ08) — popularidade nao e sinonimo de desenvolvimento ativo.
  • Limitacoes: coleta em um unico instante, teto de 1.000 resultados da propria API, e comparacao com uma fonte externa (Octoverse) que cobre uma populacao mais ampla.
